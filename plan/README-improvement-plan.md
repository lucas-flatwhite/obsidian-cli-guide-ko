# README 개선 계획

작성일: 2026-07-22
대상 파일: `README.md`, `README.en.md`

## 1. 배경 및 현황 진단

현재 `README.md`는 소개 / 미리보기 / 배포 / 로컬 실행 / 파일 구조 / 주요 기능 / 기술 스택 / 라이선스 순으로 구성되어 있고, 기본적인 정보는 잘 갖춰져 있다. 다만 아래와 같은 개선 여지가 있다.

- **스크린샷·데모 이미지 부재**: "미리보기" 섹션이 표(텍스트)로만 되어 있어 실제 사이트의 톤앤매너(다크 모던 디자인)를 README만 보고 파악하기 어렵다.
- **기여(Contributing) 가이드 부재**: 오탈자 수정, 명령어 추가/갱신, 번역 개선 등 외부 기여를 받을 수 있는 성격의 프로젝트인데 기여 방법 안내가 없다.
- **뱃지(Badges) 부재**: 배포 상태, 라이선스, 최근 커밋 등의 뱃지가 없어 저장소 신뢰도·상태를 한눈에 파악하기 어렵다.
- **콘텐츠 최신성/출처 표기 미흡**: 원본 Obsidian CLI 문서 기준 버전이나 최종 동기화 시점이 명시되어 있지 않아, 가이드가 최신 CLI 버전을 반영하는지 알기 어렵다.
- **로컬 실행 방법이 Python 전용**: `python3 -m http.server`만 안내되어 있어 Node.js 기반 개발 환경(예: `npx serve`, `live-server`) 사용자에 대한 대안이 없다.
- **한/영 README 동기화 리스크**: 두 파일이 수동으로 병행 관리되는데, 향후 한쪽만 갱신되어 내용이 어긋날 위험을 막을 장치(예: 안내 문구, 체크리스트)가 없다.
- **목차(TOC) 부재**: 문서 길이가 늘어나는 추세라 목차가 있으면 탐색성이 좋아진다.
- **이슈/피드백 채널 안내 부재**: 콘텐츠 오류(잘못된 명령어 설명 등) 제보 경로가 명시되어 있지 않다.

## 2. 개선 목표

1. 신규 방문자가 README만 보고도 프로젝트의 목적, 상태, 사용법, 기여 방법을 30초 안에 파악할 수 있게 한다.
2. 시각 자료(스크린샷)로 실제 사이트 품질을 미리 보여준다.
3. 기여 진입 장벽을 낮춘다.
4. 한/영 문서 간 정보 정합성을 유지할 수 있는 최소 장치를 마련한다.

## 3. 세부 개선 항목

### 3.1 상단부
- [ ] 저장소 상단에 뱃지 추가: 배포 상태(GitHub Actions), 라이선스(MIT), (선택) 마지막 커밋
- [ ] 짧은 목차(TOC) 추가 (소개 / 미리보기 / 배포 / 로컬 실행 / 기여 / 라이선스)

### 3.2 미리보기 섹션 보강
- [ ] 실제 사이트 스크린샷 1~2장 추가 (예: `docs/assets/screenshot-hero.png`, `docs/assets/screenshot-commands.png`)
- [ ] 스크린샷을 위한 `docs/assets/` 폴더 신설 및 이미지 첨부 가이드 마련
- [ ] 기존 표 형식 미리보기는 유지하되 이미지와 함께 배치해 보완

### 3.3 콘텐츠 출처/최신성 표기
- [ ] "원본 문서" 항목 옆에 최종 동기화 기준일 또는 참고 Obsidian 버전 표기 추가
- [ ] 콘텐츠 갱신 시 이 날짜를 함께 업데이트하도록 안내 문구 추가

### 3.4 로컬 실행 섹션 보강
- [ ] Python 방법 외에 Node.js 기반 대안 명령 추가 (`npx serve .` 등)
- [ ] VS Code Live Server 확장 사용법 한 줄 안내 추가(선택)

### 3.5 기여 가이드(Contributing) 섹션 신설
- [ ] "🤝 기여하기" 섹션 추가: 오탈자/명령어 오류 제보, 번역 개선, PR 절차(Fork → Branch → PR) 간단 안내
- [ ] 이슈 등록 시 참고할 템플릿 유무 확인 후 링크 (없으면 생략 가능)
- [ ] 한/영 README 동시 수정이 필요한 변경 사항은 두 파일을 함께 갱신해달라는 문구 명시

### 3.6 기타 다듬기
- [ ] "파일 구조" 섹션에 `docs/assets/`(신설 시) 반영
- [ ] 오탈자·띄어쓰기 등 문구 정리
- [ ] README.md ↔ README.en.md 섹션 순서/제목 1:1 대응 재확인

## 4. 적용 순서 (제안)

1. 스크린샷 촬영 및 `docs/assets/` 폴더 구성
2. README.md에 뱃지 · 목차 · 스크린샷 · 로컬 실행 대안 · 기여 섹션 반영
3. README.en.md에 동일 구조로 번역 반영 (섹션 1:1 대응 확인)
4. 두 파일 diff 비교로 정합성 재확인 후 커밋

## 5. 리스크 및 참고사항

- 스크린샷은 실제 배포 사이트(https://lucas-flatwhite.github.io/obsidian-cli-guide-ko/)를 캡처해야 하므로, 사이트 디자인이 변경될 때마다 스크린샷도 함께 갱신이 필요함 — README 하단에 "스크린샷은 실제 화면과 다를 수 있음" 문구를 넣어 유지보수 부담을 낮추는 것도 고려.
- 뱃지는 외부 서비스(shields.io 등) 의존이 생기므로, 정적 사이트의 "빌드 도구 없음" 철학과 상충하지 않는 선에서 최소한으로 사용.
- 이 계획은 실행 계획(planning) 문서이며, 실제 README 반영은 별도 작업으로 진행한다.
